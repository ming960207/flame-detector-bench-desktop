## 一、项目摘要

本项目拟建设一套用于火焰探测器成品检测的定制型自动检测台，集成上位机软件、PLC/HMI 控制、检测工装、继电器及测温/状态采集设备、现场结构件和配套电气部件，实现火焰探测器成品的标准化检测、过程控制、结果判定和审计追溯。

项目当前已形成 React/TypeScript 上位机、Node.js 后端、PLC/HMI 资产、四阶段工艺契约和离线上位机闭环验证基础。离线闭环已覆盖“安全未就绪禁止启动、初始化、移动热源、爆闪干扰、电磁占位、回初始位确认、完成、六台探测器批次门禁、本地审计记录”等关键逻辑。2026年7月27日项目静态门禁复核结果为现场发布未就绪：资产基线存在 AWL、工序流程、HMI 完整导入包和 HMI 手动页 4 项哈希漂移，PLC/HMI 工程也尚未完成与最新受控资产匹配的导入、编译、CRC 校验和现场 FAT/SAT。因此，本报告将软件离线验证与现场投运证据严格区分。

**综合结论：项目技术路线可行、建设必要性明确，经济上具备立项论证基础，建议采用“有条件批准”的方式推进。** 在现场使用和固定资产最终验收前，必须完成 PLC/HMI 版本统一、硬件安全回路及限位反馈验证、逐点 I/O 对照、FAT/SAT、操作培训和财务实际效益参数补录。

## 三、建设背景与必要性

### 3.1 建设背景

火焰探测器成品需要经过多工艺阶段的响应、抗干扰、动作反馈和结果确认。若主要依赖人工操作或分散设备完成，容易出现测试步骤不一致、过程参数记录不完整、检测结果与产品批次关联不足、异常复测依赖个人经验等问题。

现有项目已经具备检测台上位机软件和 PLC/HMI 资产基础，项目目标已从单一界面展示扩展到工艺状态管理、六台探测器批次结果门禁、报告管理和本地审计。建设固定资产检测台有利于把软件能力、检测工装和现场控制设备固化为可重复使用的生产检测能力。

### 3.2 建设必要性

1. **统一检测工艺。** 将初始化、移动热源、爆闪干扰、电磁占位、回初始位确认等阶段纳入受控流程，降低人为漏检和错序操作风险。
2. **提升质量判定一致性。** 当前离线闭环设计要求同一批次六台探测器的地址、时效、通信状态、火警响应和 PASS 结论同时满足门禁后方可放行报告。
3. **加强过程追溯。** 上位机可对命令、状态快照、离线适配器输入和探测器结果形成追加式审计链，便于追踪检测过程和异常原因。
4. **降低重复劳动。** 通过 PLC/HMI 与上位机协同，减少人工逐项操作、人工汇总和重复录入报告的工作量。
5. **支撑后续扩展。** 项目已具备本地化配置、报告管理、通信状态上报和检测流程扩展基础，可在完成现场接口收敛后继续扩展产品型号和测试工艺。

## 四、建设内容与技术方案

### 4.1 总体组成

本项目建议按“一套专用检测台”进行资产登记，内部由以下部分组成：

| 子系统 | 主要内容 | 作用 |
|---|---|---|
| 检测工装与结构件 | 火焰探测器安装、定位、移动/回位和必要的防护结构 | 保证被测产品位置稳定、工艺动作可重复 |
| PLC/HMI 控制系统 | S7-200 SMART 候选工程、HMI 控制画面、状态和命令变量 | 执行现场顺序控制、联锁、状态显示和人工授权操作 |
| 上位机软件 | React/Vite 前端、Node.js/Express 后端、WebSocket、Modbus/S7 适配和本地存储 | 负责工艺管理、过程显示、设备状态、批次门禁和报告管理 |
| 采集与执行部件 | 继电器模块、数字量 I/O、温度/状态采集、火焰探测器通信 | 完成测试信号采集和检测动作执行 |
| 数据与审计 | 本地配置、离线审计 JSONL、报告导出和必要的状态上报接口 | 保存检测过程、结果和异常证据 |

### 4.2 工艺流程

项目当前受控逻辑的主要阶段为：

**初始化（INIT） → 移动热源（HEAT） → 爆闪干扰（FLASH） → 电磁占位（EMC） → 回初始位确认（RETURN_HOME） → 完成（COMPLETE）。**

其中，电磁干扰阶段完成后不能直接放行质量报告，必须完成回初始位确认；仅在当前批次六台探测器结果均满足门禁、流程状态达到 COMPLETE 且审计记录完整时，报告才允许放行。STOP 应原子中止当前批次并永久阻止该批次报告。

### 4.3 主要技术特点

1. **四阶段闭环工艺。** 将工艺推进从页面计时器逻辑收敛为可审计的高层命令和状态序列。
2. **六台探测器批次门禁。** 对当前批次的设备地址、数据时效、通信状态、火警响应和 PASS 结论进行联合校验。
3. **命令幂等与状态版本。** 高层命令带 requestId、序号和拒绝原因；重复请求返回原处置，迟到消息不会使状态回退。
4. **本地离线运行。** 默认仅绑定本机服务，不依赖外部网络即可验证上位机内部流程；外部上传不应绕过授权和报告门禁。
5. **审计链防篡改检测。** 本地审计采用追加式 JSONL，并使用前序哈希和当前哈希校验完整性，发现链路损坏时阻止查询或导出。
6. **可维护的软硬件分层。** 前端负责流程界面和报告交互，后端负责设备服务、命令裁决和审计，PLC/HMI 负责现场执行与安全联锁，便于后续分层验收。

## 五、可行性分析

### 5.1 技术可行性

项目技术路线采用成熟的工业控制与本地应用组合：前端使用 React、TypeScript 和 Vite，后端使用 Node.js、Express、WebSocket 与 Modbus/S7 相关适配能力，现场通过 PLC/HMI 执行工艺动作。项目资料已形成配置、I/O 契约、离线闭环服务和自动化测试，说明软件架构具备继续工程化落地的基础。

已具备的验证基础包括：

- 安全未就绪时拒绝 START；
- START、STOP、RESET 和批次提交具备请求标识、单调序号和幂等处理；
- 四阶段工艺在 EMC 后强制进入回初始位确认；
- 当前批次六台探测器结果不完整或异常时报告保持阻止；
- STOP 后当前批次报告不可放行；
- 本地审计事件具备前序哈希和当前哈希；
- 前端与后端已有构建和离线闭环自动化测试基础。

本次项目核验中，前端 Vite 构建和后端 TypeScript 构建均通过；但 `npm run verify:field-readiness` 返回 `readyForFieldRelease=false`、`baseline.status=drifted`。该结果属于现场发布阻断项，不影响离线上位机软件继续开发和验证，但必须在现场使用前完成资产重新审查、基线更新或回退到受控版本，并完成 PLC/HMI 工程导入、编译、CRC 和 FAT 证据闭环。

但下列事项仍属于现场技术可行性的前置条件，不能以离线软件测试替代：

- 将审核后的 PLC AWL 导入最新匹配的 `项目 1.smart` 工程并无错误编译；
- 将 HMI 变量和控制资产导入可编辑工程，确认变量权限、报警自动恢复和手动操作边界；
- 获取 PLC 在线版本、CPU/固件信息、程序 CRC 或等价校验和；
- 完成电气 I/O 逐点对照，验证安全回路、急停、门禁、限位和运动反馈；
- 对电磁阶段的实际输出、动作反馈和异常处置进行受控 FAT/SAT；
- 建立 PLC、HMI、上位机和六台探测器之间唯一且版本化的 I/O/批次结果契约。

**判断：软件架构和离线闭环可行；现场自动控制的最终可行性为“待前置条件关闭后确认”。**

### 5.2 工艺与质量可行性

项目能够将检测步骤、设备状态、批次结果和报告输出纳入统一流程，具备提升检测一致性和追溯性的价值。特别是 EMC 后回初始位确认和六台探测器联合门禁，可减少“页面显示完成但机构未回位”或“部分探测器未形成有效结果却提交报告”的风险。

质量方面建议将以下内容列为验收必测项：

| 验收项 | 目标 |
|---|---|
| 启动安全门禁 | 安全未就绪时无法启动；异常状态有明确拒绝原因 |
| 阶段顺序 | 仅允许按受控顺序推进，不允许跳过回初始位确认 |
| 机构反馈 | 每个移动方向具备到位、超时、互锁和故障锁存验证 |
| 探测器批次 | 六台设备的地址、时效、通信和 PASS 结果均满足门禁 |
| 中止行为 | STOP 后输出安全收敛，当前批次报告永久阻止 |
| 报告完整性 | 报告与批次、设备、操作者和审计链关联，禁止无效数据自动上传 |
| 版本追溯 | PLC、HMI、上位机和配置具有可记录的版本/哈希 |

### 5.3 运维可行性

设备软件采用本地部署方式，运行环境和配置文件边界明确，适合在生产现场离线或受控网络中使用。日常运维建议由设备管理员负责配置备份、版本登记、权限管理和审计文件归档；由维修人员负责 I/O、继电器、传感器、工装和安全回路检查；由软件维护人员负责上位机版本和接口适配。

建议建立以下制度化文件：设备操作规程、日点检/周点检表、年度校验或预防性维护计划、PLC/HMI/上位机版本清单、I/O 点位表、异常处置卡、备件清单和验收记录。

### 5.4 经济可行性

本项目目前可确认的投资基数为 100,000.00 元，未提供实际人工成本、当前检测节拍、年检测批次、返工率和维护费用，因此不直接虚构年度收益。建议财务和申请部门按下列口径补录：

> 年净效益 = 节省的人工成本 + 减少的返工/复测成本 + 减少的质量损失与报告管理成本 + 可确认的产能贡献 − 年运维成本
>
> 静态投资回收期 = 100,000 ÷ 年净效益

在仅用于立项敏感性分析的示例情景下：

| 年净效益（示例） | 静态投资回收期 | 说明 |
|---:|---:|---|
| 40,000 元 | 2.50 年 | 偏保守情景 |
| 60,000 元 | 1.67 年 | 中等改善情景 |
| 80,000 元 | 1.25 年 | 较充分利用情景 |
| 100,000 元 | 1.00 年 | 年净效益达到投资额情景 |

该表仅用于说明投资敏感性，不构成已实现收益承诺。若公司要求静态回收期不超过 2 年，则年净效益至少应达到 50,000 元；若要求不超过 3 年，则年净效益至少应达到 33,333.33 元。以专用设备预计 10 年使用期限计，即使不考虑残值，设备在通过验收并达到稳定使用率后仍具备较长的服务周期。

**经济判断：预算规模与专用检测台建设内容基本匹配；能否达到目标回收期取决于年检测量、人工替代量和质量损失改善数据，建议在采购合同或立项审批中补充实际测算表。**

## 八、主要风险及控制措施

| 风险 | 当前表现 | 控制措施 |
|---|---|---|
| PLC/HMI 版本不一致 | 当前状态记录为 PLC binary import pending、HMI project import pending；静态门禁另发现 AWL、工序流程、HMI 完整导入包和 HMI 手动页 4 项基线哈希漂移 | 统一工程版本，审查漂移资产并记录 CRC/哈希；未完成前禁止现场下载 |
| 安全回路或限位反馈不足 | 审计资料指出仍需验证硬件安全回路、垂直到位和运动超时 | 由电气/设备负责人完成硬件安全验收；每轴配置到位、超时、互锁和故障锁存 |
| I/O 语义漂移 | 历史上存在 PLC、HMI、上位机点位含义不一致风险 | 建立唯一版本化 I/O 契约，禁止以文件名或端口连通替代逐点验证 |
| 专用设备使用率不足 | 设备主要服务火焰探测器成品，跨产品复用能力有限 | 立项前确认年检测量、产品型号和排产；明确后续工艺扩展边界 |
| 报告误上传或数据不完整 | 旧路径存在自动上传和无效报告风险 | 现场版默认本地审计；仅在批次门禁、数据完整性和授权操作员确认后上传 |
| 配置与版本不可追溯 | PLC、HMI、上位机和现场配置存在多来源管理风险 | 设置唯一配置源、版本号、生效记录、备份恢复和变更审批 |
| 网络和权限风险 | 现场控制服务需要限制访问范围和操作权限 | 默认本机/受控网卡绑定，限制跨网访问，设置操作员/维护员权限并留存审计 |

## 九、结论与审批建议

### 9.1 综合结论

本项目建设目标明确，设备为火焰探测器成品检测的专用自动化固定资产。基于现有项目资料，软件架构、离线上位机闭环、四阶段工艺模型、六台探测器批次门禁和本地审计能力具备实施基础；设备具有改善检测标准化、过程一致性和质量追溯的预期价值。按 1 台（套）、预算 100,000.00 元进行固定资产论证，在设备使用期限和潜在人工/质量成本改善方面具备合理性。

但是，现阶段尚不能证明 PLC、HMI、上位机和实体检测台已经形成可直接投运的真实闭环。特别是 PLC/HMI 导入、编译、CRC、I/O 逐点核对、安全回路、限位反馈和 FAT/SAT 仍是决定现场可行性和固定资产最终验收的关键证据。

### 9.2 审批建议

建议：**原则同意立项/预算论证，按“有条件批准、完成现场验收后正式投运”的方式推进。**

批准条件如下：

- 采购或开发合同中明确设备、软件、工程文件、版本/CRC、培训和验收交付物；
- 在现场使用前关闭 PLC/HMI 导入编译、I/O 对照、安全回路、限位反馈和 FAT/SAT 问题；
- 补充真实年检测量、人工成本、返工/复测成本和运维费用，形成财务版回收期测算；
- 未完成上述条件前，项目仅可作为设计/离线验证成果，不得将其作为现场自动控制或产品质量合格认证的替代证据。
