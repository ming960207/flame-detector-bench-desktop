# 浅绿色检测台独立界面设计规格

## 任务范围

本目录是现有“上位机界面原型版”之外的独立设计探索，不修改现有 `index.tsx`、现有 React 组件、生产 CSS 或构建入口。目标是为“理工光科智慧生产 - 火焰探测器检测台”制作一套浅绿色主色系的高品质桌面监控界面，用于现场操作员在 1280×1080 工位屏上快速判断设备是否可运行、检测链路是否完整、六台探测器当前结果是否可信，以及当前工序是否允许继续。

## 受众与场景

主要受众是生产检验人员、设备调试人员和现场质量负责人。界面不是宣传页，而是一个需要在几秒内完成状态扫描的操作台：第一眼应看到整机状态和安全/通信结论；第二眼能定位 PLC、探测器或工序中的异常；第三眼才进入波形、检测批次和记录等细节。屏幕距离约 1 米，正文与状态标签需要保持高对比度，不能靠细小文字或霓虹发光来传递层级。

## 共同信息骨架

- 顶部：WUTOS / 理工光科标识、页面标题、当前时间、通信状态和当前产品型号。
- 主要状态：检测台“可运行 / 等待 / 告警”结论，当前工序与安全链路提示。
- 设备视觉：沿用项目中的真实检测台照片，不用 CSS 剪影代替实体设备。
- 设备信号：PLC I/O、联锁、报警和继电器状态，用短标签和明确颜色表达。
- 探测器批次：6 台探测器、A/B 类合格、复测和失败状态，保留 GHT-1050-02 型号语境。
- 过程进度：初始化、移动热源、爆闪干扰、电磁占位、回初始位、记录六段流程。
- 证据与记录：最近一次事件、检测批次摘要、报告生成或上传状态。

## 视觉基调

“浅绿色”不是把所有组件涂成薄荷色，而是用低饱和的植物绿建立可靠、清洁、可持续运行的感受，再用深松柏绿承载文字和结论，用一处较亮的嫩绿强调正在发生的动作。背景以暖白、雾绿和极浅灰绿为主，边界采用细线和实体留白，不使用霓虹文字、过度阴影、紫色渐变、装饰性 emoji 或无意义的统计数字。三版需要共用真实内容，但分别探索清透纵向导航、空间化设备舞台和高密度指挥台三种结构，避免只换颜色的换皮方案。

## 输出规格与约束

- 每个方向是一份可直接用浏览器打开的 HTML，目标视口为 1280×1080。
- 使用项目内真实资产：`public/wutos-assets/wutos-logo-real.png` 与 `public/wutos-assets/machine-real.png`。
- 所有数据为界面方向验证用的静态快照，标注为“示意快照”，不伪装成后端实时数据。
- 原型放在 `design-demos/green-interface/`，不被现有 Vite 入口引用，不改现有运行界面。
- 先输出三版截图等待选择；用户选定后，才为选定方向补交互、状态切换和最终规格。

## Form 推导

1. 叙事角色：这是“操作前确认 + 检测中监视”的数据主屏，不是欢迎页。
2. 观众距离：现场 1 米观看，因此结论字号、状态形状和流程节点必须先于细节。
3. 温度：专业、清洁、克制，但不能像医疗后台一样失去设备感。
4. 容量：一屏承载一个主设备锚点、一个检测结论、六台批次状态和一条流程轨道。
5. 视觉母题：火焰探测器检测的核心是“光信号经过检测台后被裁决”，因此用光路式细线、检测窗口和分段轨道表达从设备到结论的过程，不依赖发光字体。

## 三版选择门

本文件对应三版真实初稿：A「清透序列」、B「苔原台」、C「翡翠指挥」。用户选择方向前不创建 `direction-approved.md`，也不把任何一版接入生产入口。
